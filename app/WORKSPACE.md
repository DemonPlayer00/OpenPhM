# OpenPhM 工作区排布方案

> 面向制谱器的界面组织方案。当前已在 `app/` 中实现为**可切换的工作区预设**（`--ws compose|timeline|perform|debug`），
> 面板停靠与布局持久化列为演进项（见第 6 节）。

---

## 1. 设计原则

1. **演奏区永远在场**。它是唯一直接对应"游戏内表现"的视图，其余面板都是围绕它的辅助。任何预设都不隐藏演奏区。
2. **按任务显隐，而不是把面板堆满**。制谱、对拍、查表演、排障是四种不同任务，需要的视图不同；把全部面板同时打开只会挤压演奏区。
3. **空闲成本由预设决定**。面板越多，空闲态的重绘原因越多。预设切换同时应改变空闲开销（见第 5 节实测）。
   **面板的更新成本由广播话题决定，而不是由"面板开没开"决定**：每个面板只在 EditCore 的广播把它置脏时才重建，
   话题无关时一帧都不参与（例如改透明度/流速事件不重建任何面板缓存）。
4. **尺寸用比例而非像素**。时间轴高度按中央区高度的比例计算（并 clamp），列表宽度按工作区给定，以适配分数 DPI（scale 1.25/1.5）与不同分辨率。
5. **不引入 dock 系统直到数据模型稳定**。可停靠面板会带来布局持久化、拖拽命中测试、序列化等一大堆问题；在 opm 数据模型与 codec 固化前，硬编码的几个预设性价比更高（第 6 节给出触发条件）。

## 2. 面板清单与职责

| 面板 | 职责 | 数据来源（opm 模型） |
|---|---|---|
| **演奏区** | 判定线 + 音符的实时预览，含判定线旋转/透明度/表演；唯一能验证"游戏内会变成什么样"的视图 | `judgeLines[]` / `notes` / 事件轨道 |
| **时间轴** | 以时间为横轴的全局导航：拍线、可见窗口、播放头；**当前轨道的事件曲线 + 事件条 + 当前线的子音符**；点击/拖拽定位 | `bpmList`（拍线）+ 选中线的 `layers[]` 与 `notes[].time` |
| **判定线树**（左侧，四级） | 判定线 → 事件轨道 → 事件 → 子音符。判定线行尾直接显示该线**此刻**的表演值（x/y/旋转/透明度），事件是否生效先看数字 | `judgeLines[]` / `layers[]` / `notes[]` |
| **音符列表**（树的一部分） | 当前判定线的**子音符**，精确数值查看与批量选择；**必须虚拟化** | 选中线的 `notes` |
| **属性检查器** | 选中对象的字段编辑 | 选中的 `Note` / `Event` |
| **事件面板**（已实现，树的一部分） | 当前线的五条轨道（事件数 / 播放头处取值 / 值域）+ 事件列表（起止拍秒、起止值、缓动）；两个动作：`在播放头切分`、`删除选中` | `judgeLines[].layers[*].{moveX,…}` |
| **诊断** | 帧时间、UI 构建耗时、实例数、适配器/后端、缩放、空闲 fps；**更新广播**区：已应用条数、最近一条广播、话题、谱面重建耗时、重建/跳过计数 | 运行时 + 更新广播 |
| **状态栏** | 缩放 / 播放头 / 可见实例 / 构建耗时 / 帧号 / **广播与重建计数**（`广播 N  重建 谱面x/列表y/元z/检查w  跳过 …`，`⏳ 等广播` 表示命令已受理、界面在等 update 广播）/ 适配器 | 运行时 + 更新广播 |

## 5. 空闲成本（实测，2560×1600@240Hz）

工作区预设不仅决定布局，也决定空闲时的重绘量。`--idle-seconds` 用于测量：

| 预设 | 空闲 fps（`--idle-fps 1`） |
|---|---|
| 制谱 | 2.50 |
| 时间轴 | 2.50 |
| 表演 | 2.75 |
| 调试 | 2.25 |

四者相近 ⇒ **空闲成本由 egui 的强制心跳主导，而非面板数量**；面板数量影响的是工作态的 UI 构建耗时（实测 0.14 ~ 1.13 ms）。

**节奏规则（已实现）**
- **工作态**（播放中 / 正在按住拖拽 / 首帧布局稳定前 / bench 活跃阶段）⇒ 连续 `request_repaint()`，由 vsync 封顶到屏幕刷新率（实测 239.6 fps @240 Hz）。
- **空闲态**（画面无更新）⇒ 不连续重绘，只保留 `--idle-fps` 心跳（默认 1，实测约 2.5 fps 因 eframe 每次唤醒多渲染一帧）；`--idle-fps 0` 时为纯事件驱动（实测 1.25 fps，即每个空闲窗口仅收尾一帧）。
- ⚠️ **活动信号不能用 `egui_wants_pointer_input()`**——它的语义是"egui 想接收指针事件"，鼠标**悬停**即为真；误用会让空闲态在鼠标停靠时被判为工作态（实测把空闲 fps 顶到 88~152）。正确信号是 `egui_is_using_pointer()`（正在按住/拖拽）。

## 6. 演进路线

1. **现在（已实现）**：硬编码四预设 + 面板显隐/比例。
2. **下一步**：事件图层树面板（opm 的判定线/层/轨道需要它才能编辑）；快捷键接入（注意 IME 焦点）。
3. **布局持久化**：把 `Workspace` 与各面板尺寸写进 egui persistence（或自存 JSON 到工程目录），跨会话恢复。
4. **可停靠化**：仅当满足以下条件之一才做——(a) 用户明确要求自定义布局；(b) 面板数量 > 8，预设组合开始不够用。届时优先 `egui_dock`（MIT，社区维护），自研 dock 是最后选项；自研需自行解决拖拽命中测试、最小尺寸约束、序列化与 DPI 变更下的尺寸恢复。
5. **多显示器**：egui 支持多 viewport（`show_viewport_deferred`），"把演奏区放到第二块屏"是真实需求，但会引入跨 viewport 状态同步与 IME 焦点问题，排在可停靠化之后。

---

## 7. 与分数 DPI 的约定

- 所有面板尺寸用**逻辑点**（egui points）；仅在与 wgpu 交界处乘 `pixels_per_point`（演奏区 viewport 正是如此）。
- 演奏区的映射自检：`--verify-align` 用同一批 RPE 坐标分别由自研管线（品红方块）与 egui 画笔（青十字）绘制，**scale=1 与 scale=1.5 下必须重合**。任何改动演奏区布局的提交都应跑一次。
- 时间轴与列表的行高取自 `ui.text_style_height`，避免在分数缩放下手写像素值。
